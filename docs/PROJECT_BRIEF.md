# 멀티업로더 프로젝트 브리프

## 목표

본 프로젝트의 운영 목표는 소유하거나 배포 권한이 있는 YouTube Shorts를 사용자가
명시한 플랫폼에 정확히 배포하는 Windows 전용 환경을 만드는 것이다. 첫 운영
마일스톤은 영상 2편에 대한 플랫폼별 배포와 직접 검증이다.

## 이번 단계의 범위

현재 구현은 Windows 로컬 웹앱을 통해 채널·플랫폼 설정, 계정 연결, 영상 선택,
게시 미리보기, 배포 실행 및 결과 조회를 제공한다. 상세 사용법은
[웹앱 사용법](WEB_APP_GUIDE.md)을 따른다.

최초 준비 단계에는 다음 작업을 수행했다.

1. 원본 저장소 이력과 MIT LICENSE를 보존한 복사
2. 원본 기준 커밋과 파일 트리 확인
3. `AGENTS.md`와 `.agents/skills/shorts-upload` 검토
4. Windows, Python, uv, Chrome, ffmpeg 및 Codex 도구 진단
5. 프로젝트 상태와 Windows 운영 절차 문서화

첫 2편 배포 검증은 Windows 운영 준비 후 진행할 후속 마일스톤이다.

## 변경 및 배포 원칙

- 모든 수정은 기능 브랜치에서만 수행한다. `main`에 직접 커밋하거나 자동 병합하지
  않는다.
- 원본 저장소는 `upstream`, 운영 대상 저장소는 `origin`으로 구분한다.
- `.env`, 토큰, 비밀번호, 쿠키, 브라우저 프로필, 다운로드 영상, 스크린샷, HTML
  캡처, SQLite DB와 실제 게시 이력은 로컬 전용이다.
- 플랫폼, 채널, 계정 핸들, 검증 URL, 광고/캠페인 정책을 추측하지 않는다.
- 로그인, 2FA, CAPTCHA, 저작권, 권한, 계정 전환 또는 유료 홍보 판단이 나타나면
  중단하고 사용자 결정을 기다린다.
- 재게시 전에는 해당 플랫폼에서 영상이 실제로 누락됐다는 최신 직접 검증이 필요하다.

## 첫 2편 검증의 완료 조건

후속 단계에서 사용자가 대상 플랫폼과 계정을 명시하고 게시를 승인한 뒤에만 다음
조건으로 완료를 판단한다.

- 선택된 두 영상 ID가 고정되고 오래된 영상부터 처리됨
- 각 `영상 × 플랫폼` 셀이 `verified`, `already`, 정책상 제외, 또는 정확한 차단
  사유 중 하나로 귀결됨
- 게시된 본문이 준비된 `post_text`와 일치함
- 가능한 경우 플랫폼별 실제 게시물 URL과 직접 검증 증거가 로컬 상태에 기록됨
- 중복 게시가 없고 민감한 로컬 산출물이 Git에 포함되지 않음
