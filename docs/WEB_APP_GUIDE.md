# 멀티업로더 웹앱 사용법

멀티업로더는 **Windows PC에서 실행하고 웹브라우저로 사용하는 로컬 웹앱**이다.
화면과 Python 서버가 같은 PC에서 동작한다. 기존 Playwright 엔진이 전용 Chrome
프로필을 사용해 Instagram, Threads, TikTok, LinkedIn, Facebook, Naver Clip에 배포한다.

## 실행

PowerShell 7에서 프로젝트 폴더를 열고 실행한다.

```powershell
.\Start-Multiuploader.ps1
```

처음 실행하면 uv가 잠금 파일 기준으로 의존성을 설치하고 브라우저를 연다.
접속 주소는 `http://127.0.0.1:8765`이다. 터미널은 앱을 사용하는 동안 열어 둔다.
종료는 해당 터미널의 `Ctrl+C`다.

이 PC에서 확인된 uv 패키지 빌드 격리 문제를 피하기 위해 시작 스크립트는
`uv sync --locked --no-install-project`로 의존성을 설치하고 소스 모듈을 직접 실행한다.
Python 서버는 표준 라이브러리를 사용하므로 별도 Node.js 설치나 프런트엔드 빌드가
필요하지 않다.

포트를 바꾸거나 브라우저 자동 열기를 생략할 수 있다.

```powershell
.\Start-Multiuploader.ps1 -Port 8770 -NoBrowser
```

PowerShell 실행 정책이 스크립트를 막으면 정책을 변경하지 않고 직접 실행할 수 있다.

```powershell
uv sync --locked --no-install-project
$env:PYTHONPATH = (Resolve-Path .\src).Path
$env:PYTHONUTF8 = '1'
$env:PATH = "$(Resolve-Path .\.venv\Scripts);$env:PATH"
.\.venv\Scripts\python.exe -m shorts_distributor.web --open
```

## 처음 설정하는 순서

1. **계정 및 설정**에서 YouTube 채널의 `@핸들` 또는 채널 URL을 입력한다.
2. 사용할 플랫폼을 선택하고 해당 계정 핸들·검증 URL을 입력한 뒤 **설정 저장**을
   누른다. 첫 선택 수의 기본값은 2편이다.
3. 플랫폼별 **로그인 연결**을 누른다. 열린 Chrome에서 직접 로그인하고 웹앱으로
   돌아와 **로그인 완료**를 누른다. 공유 프로필을 선택해도 플랫폼별 로그인이 필요하다.
4. **배포 작업 → 환경 점검**에서 도구와 로그인 상태를 확인한다.
5. **채널 영상 불러오기**를 누른다. 조회 범위의 새로운 후보를 표시하며, 설정한
   선택 수만큼 기본 선택한다. 체크박스로 바꾸거나 11자리 영상 ID를 직접 입력할 수 있다.
6. 대상 플랫폼을 확인하고 **미리보기 만들기**를 누른다. 영상 다운로드·코덱 확인·
   콘텐츠 정책 적용 후 오래된 순서와 최종 게시 문구를 표시한다.
7. 작업 기록에서 결과를 열어 다시 확인할 수 있다.

설정은 로컬 `.env`에 저장된다. 화면에는 설정한 계정·검증 URL만 나타나며 비밀번호를
입력하는 기능은 없다. 로그인 프로필은 `data/profiles/`, 웹앱 작업은 `data/web/jobs/`,
게시 상태는 기존 `data/state.db`를 사용한다.

## 배포 실행

앱 시작의 기본값은 준비 모드다. 준비 모드에서도 계정 연결, 영상 선택, 미리보기와
기록 확인을 사용할 수 있다. 실제 배포 버튼을 사용하려면 앱을 종료한 후 다음과 같이
시작한다.

```powershell
.\Start-Multiuploader.ps1 -EnablePublishing
```

**미리보기 만들기 → 최종 문구·플랫폼·계정 확인 → 검토한 영상 배포** 순서로 진행한다.
확인창에서 체크박스를 선택하고 `게시`를 입력하면 실행한다. 게시 모드 진입만으로
작업이 시작되는 것은 아니다.

미리보기와 배포에는 동일한 영상 ID·문구·파일을 사용한다. `.env`, 콘텐츠 정책,
영상 파일이 바뀌면 새 미리보기가 필요하다. 배포 직전에 환경 점검도 실행한다.
웹앱은 동시에 한 작업만 실행하며 로그인 프로필을 공유하는 두 웹앱의 동시 실행을 막는다.

## 결과 확인 및 복구

| 화면 상태 | 의미 |
|---|---|
| 준비됨 | 해당 셀의 미리보기가 준비됨 |
| 검증 완료 | 엔진이 게시 증거를 확인하고 검증 상태를 기록함 |
| 게시됨 / 검증 대기 | 게시 증거가 있고 추가 확인이 남아 있음 |
| 기록 있음 | 기존 게시 상태 때문에 건너뜀 |
| 정책상 제외 | 콘텐츠 정책이 해당 플랫폼을 제외함 |
| 연결 필요 / 실패 / 확인 필요 | 계정·화면·도구의 조치가 필요함 |

**작업 기록 → 검증 대기 확인**으로 기존 미검증 게시물을 다시 확인한다. 게시 URL이
있으면 게시 기록의 **게시물 열기**로 직접 확인할 수 있다. 실행 로그도 화면에서 읽을
수 있다.

게시 중단·실패는 이미 게시됐을 가능성이 있으므로 웹앱은 이전 시도와 겹치는 셀의
자동 재배포를 막는다. 재시도는 플랫폼에서 실제 누락을 확인한 뒤 기존 CLI/스킬의
단일 셀 복구 절차를 사용한다. 로그인·2FA·CAPTCHA·권한 문제는 사용자가 해결한다.

작업 중단 버튼과 서버 종료는 웹앱이 시작한 작업의 프로세스 트리를 종료한다.
진행 중인 게시를 중단했다면 플랫폼에서 완료 여부를 먼저 확인한다.

## 구현 범위와 검증

- 한국어 웹 화면: 배포 작업, 계정 및 설정, 작업 기록, 사용 가이드
- 로컬 설정 저장과 전용 Chrome 로그인 연결
- Shorts 후보 조회와 영상 ID 직접 선택
- 정책 적용 미리보기, 고정된 입력의 배포, 게시 상태 및 실행 로그
- 서버의 게시 모드 제어, 로컬 요청 인증, Host/Origin 검사
- 33개 단위/API 테스트 및 실제 Chrome 화면 테스트 통과

화면 테스트는 임시 예제 계정과 미리보기 데이터로 설정 저장·영상 선택·결과 표시·
모바일 레이아웃을 검증했다. 실제 계정의 플랫폼별 게시 성공은 계정 설정 후 확인해야
한다. 웹앱은 Windows 로컬 운영용이며 인터넷에 공개하는 서버로 배포하지 않는다.
